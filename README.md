# linux-rt-arm

A **PREEMPT_RT (hard realtime) Linux kernel package for Arch Linux ARM**,
aarch64. The official Arch [`linux-rt`](https://archlinux.org/packages/extra/x86_64/linux-rt/)
is x86_64-only; this package fills the gap for ARM boards.

| | |
|---|---|
| Kernel | **Linux 7.2.8** (latest 7.x stable at build time, 2026-09-28) |
| Preemption | `CONFIG_PREEMPT_RT=y`, `CONFIG_PREEMPT_DYNAMIC` **not set** |
| Architectures | `aarch64`: built and functionally tested in QEMU. `armv7h`: not yet (see below) |
| Base | Arch Linux ARM `linux-aarch64` 7.2.8-1 config + packaging |
| Patches | **None.** Pure upstream kernel.org tarball; RT is Kconfig-only |
| Packages | `linux-rt-arm`, `linux-rt-arm-headers` |

> **Latency status:** everything here was verified **functionally** under
> QEMU (TCG emulation). Emulated latency numbers measure the emulator, not
> the kernel, so **no latency figures are published yet**. Hardware latency
> benchmarks are still to come.

---

## How it works

Since Linux 6.12, PREEMPT_RT is part of mainline. There is no longer an
"-rt patch" to apply to get a realtime kernel. You enable
`CONFIG_PREEMPT_RT` in Kconfig, and the kernel then:

- replaces spinlocks and rwlocks with priority-inheriting, sleeping
  rt_mutex-based locks,
- forces interrupt handlers into threads (`irq/<n>-<name>` kthreads you can
  prioritise with `chrt`),
- runs softirqs and timers in preemptible thread context (`ktimers/<cpu>`),
- makes nearly all kernel code preemptible by higher-priority tasks.

This package takes Arch Linux ARM's generic multi-platform aarch64 kernel
configuration (`linux-aarch64`), applies a small, documented set of changes
(`config.rt-fragment`), and packages the result exactly like
`linux-aarch64`:

- `/boot/Image`, `/boot/Image.gz`, `/boot/dtbs/` (built with `-@` so U-Boot
  can apply overlays),
- `/boot/initramfs-linux.img`, generated by mkinitcpio via the preset
  `/etc/mkinitcpio.d/linux-rt-arm.preset`,
- modules under `/usr/lib/modules/7.2.8-1-rt-arm/`.

Because the file names in `/boot` are the same, it is a **drop-in
replacement for `linux-aarch64`**: your board's existing boot script,
extlinux.conf or systemd-boot entry keeps working without changes. The two
packages conflict, so only one can be installed at a time.

As a safety net, `prepare()` refuses to build unless, after `olddefconfig`,
`CONFIG_PREEMPT_RT=y` is set and `CONFIG_PREEMPT_DYNAMIC` is not.

### Why ALARM `linux-aarch64` as the base (and not Arch `linux-rt`)

Arch's `linux-rt` is x86_64-only. Its config is x86 and it still applies the
out-of-tree `-rt` patch queue (for example `v7.2.8-rt3`), which this project
does not use. ALARM's `linux-aarch64` already provides everything
ARM-specific: an aarch64 multi-platform config, dtbs, and the `/boot`
layout ALARM boards expect. Adapting it takes one config fragment. Adapting
`linux-rt` would mean rewriting its config, its patch handling and its boot
layout. So `linux-aarch64` is the simpler base. The only packaging
differences from `linux-aarch64` are:

- the full `linux-7.2.8.tar.xz` with its PGP signature, not the
  `linux-7.2.tar.xz` + `patch-7.2.8` pair,
- ALARM's five board patches are **dropped** (see "Known differences"),
- the chromebook (`vmlinux.kpart`) subpackage is dropped,
- `makedepends` are trimmed to what the build actually uses (no git,
  uboot-tools, vboot-utils, xmlto or docbook, since nothing uses them).

## How to use it

### Build and install on the device (native, as with any AUR package)

```sh
git clone https://github.com/KM-mostoslavski/linux-rt-arm.git
cd linux-rt-arm
# import the kernel.org signing keys once (or: gpg --locate-keys <addr>)
gpg --import keys/pgp/*.asc
makepkg -s
sudo pacman -U linux-rt-arm-7.2.8-1-aarch64.pkg.tar.zst \
               linux-rt-arm-headers-7.2.8-1-aarch64.pkg.tar.zst   # headers optional
# pacman asks to remove linux-aarch64: answer y
sudo reboot
```

This is a full kernel build: expect several hours on a 4-core board. You
need about 6 GB of free space (the build tree was 4.9 GB in our builds).

### Verify after reboot

```sh
uname -v                                  # ... SMP PREEMPT_RT ...
zgrep -E 'PREEMPT_(RT|DYNAMIC)' /proc/config.gz
# CONFIG_PREEMPT_RT=y
# (no CONFIG_PREEMPT_DYNAMIC=y line)
```

Or run the full functional check from this repo as root:
`sudo bash qa/rt-qa.sh` (needs `python`, and `rt-tests` for cyclictest and
pi_stress).

### Using it for realtime work

- Run realtime tasks with `chrt -f <prio> <cmd>` (SCHED_FIFO) or
  `chrt -r <prio> <cmd>` (SCHED_RR). Give them `CAP_SYS_NICE` or set
  `rtprio` in `/etc/security/limits.conf`.
- IRQ handlers are threads. Raise or lower a device's IRQ thread with
  `chrt -f -p <prio> $(pgrep irq/<n>-<name>)`.
- CPU isolation is built in and inactive until you enable it on the kernel
  command line, e.g. `isolcpus=domain,managed_irq,2-3 nohz_full=2-3
  rcu_nocbs=2-3`.
- The latency tracers are built in: install `rtla` / `rt-tests` and use
  `rtla timerlat`, `rtla osnoise` and `rtla hwnoise` on real hardware.
- The default CPU frequency governor is `performance` (inherited from
  ALARM), which suits RT.

### Removing it

`sudo pacman -S linux-aarch64` (pacman offers to replace `linux-rt-arm`).
The mkinitcpio hook regenerates `initramfs-linux.img` for the new kernel.

## Config provenance

The config is **ALARM `linux-aarch64` 7.2.8-1 `config`** (generated by ALARM
on 7.2.7) plus `config.rt-fragment`, run through `olddefconfig` on 7.2.8 by
`tools/genconfig.sh`. The script fails if any fragment line does not survive
`olddefconfig`. The complete resolved diff is in
[`docs/config-rt-diff.txt`](docs/config-rt-diff.txt).

### Options set on purpose (`config.rt-fragment`)

| Option | ALARM | here | Why |
|---|---|---|---|
| `PREEMPT_RT` | n | **y** | The point of the package: mainline hard-realtime preemption. |
| `PREEMPT` | y | y (kept) | Full preemption model under RT. |
| `PREEMPT_LAZY` | n | n (explicit) | Lazy preemption delays preemption of SCHED_NORMAL tasks. We want the classic full model for hard RT. |
| `PREEMPT_DYNAMIC` | y | **n** | Boot-time switchable preemption is the opposite of a fixed hard-RT kernel. Also removes the `preempt=` boot parameter and the debugfs switch. |
| `DEBUG_PREEMPT` | y | **n** | Adds checks on every `preempt_count` change. Debug overhead has no place in a production RT kernel. Arch `linux-rt` disables it too. |
| `NO_HZ_FULL` | n (`NO_HZ_IDLE`) | **y** | Lets isolated CPUs run tickless (`nohz_full=`). Inactive unless requested. Matches Arch `linux-rt`. |
| `RCU_EXPERT` | n | **y** | Needed to reach the RCU options below. The remaining RCU expert options keep their defaults (e.g. `RCU_FANOUT=64`, `RCU_FANOUT_LEAF=16`, `RCU_LAZY=n`). |
| `RCU_NOCB_CPU` | n | **y** | Offloads RCU callbacks from isolated CPUs (`rcu_nocbs=`). Inactive unless requested. |
| `RCU_BOOST` | n | **y** | Priority-boosts preempted RCU readers so RT tasks can't starve grace periods (default on RT anyway). |
| `OSNOISE_TRACER`, `TIMERLAT_TRACER`, `HWLAT_TRACER`, `SCHED_TRACER` | n | **y** | Tools for measuring latency on real hardware (`rtla`, wakeup tracers). Idle unless enabled. Matches Arch `linux-rt`. |
| `LOCALVERSION` | `"-ARCH"` | `""` | The release string comes only from the package (`7.2.8-1-rt-arm`), as Arch `linux-rt` does. |

### Side effects that follow automatically

- `VIRT_CPU_ACCOUNTING_GEN=y`, `CONTEXT_TRACKING_USER=y`,
  `TICK_CPU_ACCOUNTING` gone: required by `NO_HZ_FULL`. This adds a small,
  always-on cost on kernel entry and exit.
- `RCU_NOCB_CPU_CB_BOOST=y`, `RCU_BOOST_DELAY=500`, `TASKS_TRACE_RCU_NO_MB=y`:
  defaults.
- `TRACER_SNAPSHOT=y`, `TRACER_MAX_TRACE=y`, `GENERIC_TRACER=y`: pulled in by
  the tracers.
- `COMPACT_UNEVICTABLE_DEFAULT` 1 → 0: mainline default under RT (compaction
  of unevictable pages causes latency spikes).
- `QUEUED_RWLOCKS`, `SOFTIRQ_ON_OWN_STACK`: not used under RT (RT has its
  own rwlock and softirq implementation).
- `PREEMPT_RT_NEEDS_BH_LOCK=n`: mainline default.

### Features RT removes (Kconfig `depends on !PREEMPT_RT`)

Mainline 7.2 does not allow these together with PREEMPT_RT:

- **Legacy xtables**: `NETFILTER_XTABLES_LEGACY` and with it all
  `IP_NF_*` / `IP6_NF_*` tables and targets, arptables and legacy ebtables
  (`BRIDGE_EBT_*`, `BRIDGE_NF_EBTABLES_LEGACY`). **`iptables-legacy` does not
  work. Use `iptables-nft` (Arch's default) or `nftables`.** Existing
  iptables rulesets keep working through `iptables-nft`.
- `LEDS_TRIGGER_CPU`: the `cpu` LED trigger. Some board DTs use it for
  activity LEDs, which will simply stay unlit.
- `IR_GPIO_TX`: the GPIO bit-banging IR transmitter.
- Debug-only options that were already off or irrelevant:
  `DEBUG_VM_IRQSOFF`, `DEBUG_MUTEXES`, `DEBUG_RWSEMS`,
  `DETECT_HUNG_TASK_BLOCKER`, `SCHED_PROXY_EXEC`, `TRANSPARENT_HUGEPAGE`
  (already off in ALARM), `ENABLE_DEFAULT_TRACERS`.

## Known differences from linux-aarch64

- **No ALARM board patches.** Dropped on purpose, so the package is pure
  mainline plus config:
  - `0001` rk3399-firefly: disable pwm0,
  - `0002` PPS compatibility hack made x86-only,
  - `0003` revert of the rk3568 PCIe3 MSI move: **Rockchip RK3568 users may
    see PCIe regressions**,
  - `0004`/`0005` RPi5 RP1 PL011 binding and GPIO14/15 UART console: **no
    serial console on the RPi5 40-pin header with this kernel**. (The
    Raspberry Pi vendor kernel is a separate, later project.)
- No chromebook `vmlinux.kpart` subpackage.
- The preset has only the `default` image, like ALARM's, so there is **no
  fallback initramfs**.
- Legacy iptables is unavailable (see above).
- **No `/sys/kernel/realtime`.** That file is not in mainline. Only the
  out-of-tree RT patch queue adds it
  (`sysfs__Add__sys_kernel_realtime_entry.patch`). Tools that probe it
  (some `tuned` profiles, older scripts) should check `uname -v` for
  `PREEMPT_RT`, or `/proc/config.gz`, instead.

## Status

### aarch64: built and tested in QEMU (functional only)

Tested on QEMU `virt` (`-cpu max`, 8 vCPUs, 4 GB, TCG) with edk2 UEFI +
systemd-boot, on a stock Arch Linux ARM rootfs:

- Cross-built kernel boots directly: `#1 SMP PREEMPT_RT`, no BUG or WARNING
  splats.
- `pacman -U` replaces `linux-aarch64`, mkinitcpio regenerates
  `initramfs-linux.img`, and the system reboots from disk into
  `7.2.8-1-rt-arm`.
- `qa/rt-qa.sh`, all passing:
  - `uname -v` contains PREEMPT_RT,
  - `/proc/config.gz` has `PREEMPT_RT=y` and no `PREEMPT_DYNAMIC`,
  - there is no runtime preempt switch,
  - IRQ threads and `ktimers` threads are present,
  - `chrt -f 99` and `chrt -r 50` apply,
  - SCHED_FIFO preemption and SCHED_RR round-robin behave correctly on one
    CPU,
  - `cyclictest` runs to completion,
  - `pi_stress` (priority inheritance) runs clean,
  - dmesg has no sleeping-in-atomic splats.

  The one known deviation is `/sys/kernel/realtime` (see above).
- The unmodified PKGBUILD builds **natively** for aarch64 in a clean Arch
  Linux ARM chroot (base-devel + declared makedepends only, `makepkg` with
  the dependency and PGP checks on).

**Not tested yet:** real hardware boot on any board, and any latency
measurement. cyclictest numbers from QEMU/TCG are **not benchmarks** and are
not reported.

### armv7h (arm 32-bit): not supported yet, untested

Postponed on purpose:
- Arch Linux has no official `arm-linux-gnueabihf` cross toolchain (AUR
  only), so the fast cross-build loop used for aarch64 isn't available.
- ALARM's `linux-armv7` config would need the same RT treatment plus its
  own review of the 32-bit config fallout. Mainline's `arch/arm` does select
  `ARCH_SUPPORTS_RT`, so no technical blocker is known. It is simply
  unbuilt and unbooted.

`arch=('aarch64')` in the PKGBUILD reflects this.

## Troubleshooting

These are the problems we actually hit:

- **`/sys/kernel/realtime` missing**: expected on mainline; see "Known
  differences". Detect RT with `uname -v | grep -q PREEMPT_RT`.
- **`iptables-legacy` fails with "can't initialize iptables table
  `filter'" / "Table does not exist"**: legacy xtables is disabled under RT.
  Switch with `pacman -S iptables-nft`.
- **Install stops at "Remove linux-aarch64? [y/N]"**: this is expected, since
  the two packages ship the same `/boot/Image`. Answer `y`. With
  `--noconfirm` the default answer is **N**, so scripts must answer
  explicitly (`yes | pacman -U …`) or remove `linux-aarch64` first
  (`pacman -Rdd linux-aarch64`).
- **initramfs not updated after install**: the package triggers mkinitcpio's
  `90-mkinitcpio-install.hook` through `/usr/lib/initcpio/<kver>`, as
  `linux-aarch64` does. Check that `/boot` (often a separate FAT partition)
  is **mounted** during the install, then run
  `mkinitcpio -p linux-rt-arm`.
- **makepkg: "unknown public key"**: `gpg --import keys/pgp/*.asc`. The keys
  are Greg Kroah-Hartman (stable releases) and Linus Torvalds.
- **makepkg: "Aborting: CONFIG_PREEMPT_RT=y missing after olddefconfig"**:
  you edited `config` and something disabled RT. `PREEMPT_RT` needs
  `EXPERT=y` and `ARCH_SUPPORTS_RT=y`. Regenerate the config with
  `tools/genconfig.sh`.

## Maintaining / updating

- **New stable point release (7.2.x)**: bump `pkgver`, `_srcname`, and the
  tarball's sha256. Rebuild; `prepare()` shows any `olddefconfig` diff.
- **Regenerating the config** (e.g. a new ALARM config):
  `tools/genconfig.sh <linux-src-dir> <alarm-linux-aarch64-config>`, then
  update `config`'s sha256 in the PKGBUILD and `.SRCINFO`
  (`makepkg --printsrcinfo > .SRCINFO`). Record any new fallout in
  `docs/config-rt-diff.txt` and in this README.
- **Development harness** (`harness/`, dev-only; the PKGBUILD itself never
  cross-compiles):
  - `mkbase.sh`: one-time QEMU base image (ALARM, UEFI, systemd-boot), built
    unprivileged,
  - `cross-build.sh`: x86_64 cross `makepkg` with ccache (about 10 min cold on
    64 cores),
  - `smoke.sh`: direct `-kernel` boot on a throwaway overlay, with a 5 min
    timeout,
  - `pkgtest.sh`: `pacman -U`, reboot from disk, run `qa/rt-qa.sh`,
  - `native-validate.sh`: unmodified native aarch64 `makepkg` in a clean
    ALARM chroot through qemu-user.
